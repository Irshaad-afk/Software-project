# Five-minute Software Engineering Demonstration

1. Open the publicly accessible dashboard and explain that this tool helps
   with **weather hazard preparedness**, not precise grid-outage prediction.
2. Search for a different city, show forecast changes and inspect the hourly
   risk chart, rainfall and wind data.
3. Complete the device charging and essential-items checklist.
4. Explain Supabase email-confirmed login and browser-side publishable key.
5. Demonstrate the *unverified* community signals feed with test-only data;
   if nothing has been reported, show the empty state honestly.
6. Explain why admin moderation addresses misinformation rather than fixing
   a physical grid incident.
7. Present the diagrams in `docs/SOFTWARE_DESIGN.md` and discuss RLS.

Common viva question: “Is this AI?” Answer: This release implements an
**explainable rule-based weather hazard index**; it is not a trained ML model
and has no validation-based probability estimate.
